# Подготовка рабочего места и локальные проверки

Документ описывает базовые инструменты репозитория **до выбора кейса**. Он не является инструкцией запуска будущего приложения.

## Для новых участников

Нужны Git и Python версии 3.11 или новее для запуска скрипта проверки репозитория. Среда приложения и зависимости будут уточнены после получения задания.

```powershell
git clone https://github.com/Sashido01/MyHackathon.git
Set-Location MyHackathon
git config --local core.autocrlf false
python scripts/check_repo.py
python -m unittest discover -s scripts/tests -v
```

У владельца репозитория локальная папка `D:\MyHackathon`; остальные разработчики могут выбрать собственный путь. Не клонируйте проект повторно поверх существующей папки.

## Ubuntu 24.04

Для ноутбука с Ubuntu 24.04 используйте `python3` вместо Windows-команды `python`. Полная инструкция клонирования и проверки: [кроссплатформенная подготовка](cross-platform.md). План испытаний перед очной защитой: [demo-readiness.md](demo-readiness.md).

## Окончания строк

`.gitattributes` устанавливает LF для текстовых файлов. `core.autocrlf=false` задаётся **локально**, без изменения глобальных настроек Git. Не выключайте `core.safecrlf` ради скрытия предупреждений. Для проверки:

```powershell
git ls-files --eol .gitattributes .editorconfig README.md
```

## Командная разработка

Работайте в отдельной ветке, открывайте Pull Request в `main`. До приглашения остальных участников ветки и PR создаёт владелец. Подробности — [CONTRIBUTING.md](../CONTRIBUTING.md).

## Что проверяет CI

- `repository-checks`: UTF-8, LF, последний перевод строки, относительные ссылки Markdown и тесты скрипта проверки.
- `secret-scan`: поиск вероятных секретов инструментом Gitleaks по истории Git.

Запуск происходит на Pull Request, на push в `main` и вручную во вкладке Actions. CI **не проверяет функциональность приложения**, поскольку его пока нет. Не публикуйте секреты: проверка Gitleaks не гарантирует обнаружения всех утечек.

Правила ветки: [github-ruleset.md](github-ruleset.md).
