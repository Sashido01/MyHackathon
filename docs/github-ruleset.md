# Защита ветки `main` в GitHub

**Состояние:** инструкции для ручной настройки владельцем; создание ruleset не автоматизировано этим репозиторием.

На бесплатном GitHub правила доступны для **публичного** репозитория. В репозитории `Sashido01/MyHackathon` откройте `Settings → Rules → Rulesets → New ruleset → New branch ruleset` (названия пунктов интерфейса могут отличаться).

Установите:

1. `Ruleset name`: `protect-main`.
2. `Enforcement status`: `Active`.
3. `Target branches`: только `main` (обычно `Include default branch`).
4. `Require a pull request before merging`: включить.
5. `Required approving reviews`: 0, пока другие участники не приглашены; затем по согласованию увеличить до 1.
6. `Block force pushes`: включить.
7. `Restrict deletions`: включить.
8. `Require status checks to pass`: **не включать**, пока workflow не появится в `main` и оба задания не будут успешно выполнены в Actions.
9. `Bypass permissions`: не добавлять широкие исключения без причины.

После первого подтверждённого успешного запуска CI можно добавить обязательные проверки с точными именами заданий: `repository-checks` и `secret-scan`. Не вводите их вручную, пока GitHub не показывает реальные результаты этих checks. Если после выбора кейса добавится полноценный тестовый job, его тоже можно сделать обязательным.

Проверка: открыть новый PR и убедиться, что прямой push в `main` не разрешён, а слияние идёт через PR. **Не тестируйте защиту принудительным push.**

При ошибке конфигурации исправляйте существующий ruleset через Settings — не выключайте защиту без необходимости.
